# Native review — October 29, 2026

## Scope and result

Created a separate iPhone-native target with SwiftUI, Core Data and Apple CloudKit. This follows the owner's approved iPhone/iCloud-only direction. It does not depend on Vercel or Supabase. Existing website files, routes, database policies and live records are unchanged. No build has been uploaded or released.

Implemented tab creation/rename/private deletion, people entry, even/custom/personal expenses with tax/tip and previews, exact settlement math, payment history/undo, text summaries, atomic backups, iCloud invitation preparation/acceptance/management, and private-copy preservation when the owner stops sharing. Native fonts and mark reuse the existing branding. Large layouts use a sidebar and can use expense/settlement columns; accessibility text sizes use a single content column.

## Important limits

CloudKit code is implemented but actual collaboration has not been verified. Both development and production-environment sharing checks are release gates. Core Data's CloudKit mirroring is eventual synchronization and can take minutes or longer. The UI reports local saves and last cloud activity without claiming all participants are current.

Same-expense offline concurrent edits may resolve at record granularity. Duplicate recording from the same ledger snapshot is deduplicated, but different stale snapshots still require coordination and payment-history review. No money is moved by the app.

There is no automatic import of existing Supabase tabs. Backups restore as independent private copies with fresh identities and no retained invitations. Do not switch off the old services based on completion of this native implementation.
